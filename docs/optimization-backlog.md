# 优化建议（暂不执行，先记录）

> 用户要求：先完成 0.4.25 的复习/统计/创意造句等功能，再做性能优化。

## 列表

1. 列表虚拟滚动：只渲染视口内 30–50 行，避免一次创建 4036 个节点。
2. 搜索防抖 200ms，输入期间不重绘全量列表。
3. 搜索索引与分组缓存：分组结果按 `deck/group/query` 缓存，数据变更时失效。
4. 游戏局部重绘：只替换题目/选项区，不重建整个右面板。
5. 降低透明/模糊成本：低性能模式自动关闭 `backdrop-filter` 和大幅 `box-shadow`。
6. 视频壁纸在低性能模式自动暂停，切回窗口再恢复。
7. 统计页按需计算，图表延迟到页面打开后渲染。
8. 壁纸导入时先压缩超大图片，视频只保留必要格式。
9. 减少每次保存的全量 JSON 序列化，改为脏数据增量保存。
10. 批量导入/删除后合并多次 `saveData`，避免连续写 SQLite。
